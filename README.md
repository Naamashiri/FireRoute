# FireRoute

FireRoute הוא Backend לניתוב הולכי רגל בזמן חירום באזור מרכז תל אביב. המערכת טוענת גרף רחובות ומקלטים, מוצאת את הצומת הקרוב למיקום המשתמש, מחשבת מסלול רגיל או מסלול למקלט, ועוקבת אחרי מצב התרעות פיקוד העורף.

הפרויקט נבנה כפרויקט תיק עבודות שמדגים Backend מלא: ארכיטקטורה שכבתית, אלגוריתם Dijkstra, API מתועד, Validation, טיפול עקבי בשגיאות, עבודה עם מקור מידע חיצוני ובדיקות אוטומטיות על נתוני production.

## מה המערכת יודעת לעשות

- לאתר את צומת ההליכה הקרוב לקואורדינטות GPS.
- לחשב מסלול בין שני צמתים.
- לחשב מסלול חירום למקלט הנגיש הקרוב ביותר דרך גרף הרחובות.
- להחזיר את פרטי המקלט הפיזי, ולא רק נקודה אחרונה במסלול.
- לדווח על מצב התרעה `ACTIVE`, `QUIET` או `UNKNOWN` ועל טריות המידע.
- לסנן התרעות לאזור מרכז תל אביב בלבד.
- לשמור את המפה, המקלטים וקוד הניתוב בדפדפן לצורך שימוש אופליין לאחר ביקור מקוון ראשון.
- לעבוד במצב הדגמה ללא תלות באזעקה אמיתית.

## ארכיטקטורה

הכיוון החשוב הוא שהשכבות הפנימיות אינן תלויות בפרטים חיצוניים:

```text
HTTP / Browser
      ↓
API — Controllers, DTOs, Mappers, HTTP errors
      ↓
Application — תרחישי שימוש ותיאום הפעולות
      ↓
Domain — גרף, מסלול, מקלט, התרעה וכללי הליבה
      ↑
Infrastructure — JSON loaders, Oref HTTP, repositories, scheduler
```

- `domain` מחזיק את המודל וההחלטות העסקיות: מהו מסלול, כיצד מחשבים עלות, מהו מקלט ומהו מצב התרעה.
- `application` מפעיל תרחישי שימוש כגון חישוב מסלול, חיפוש מקלט ועדכון מצב התרעה. הוא מתאם בין רכיבי Domain ואינו מכיר HTTP או JSON חיצוני.
- `api` מתרגם בקשות HTTP ל־DTOs, מבצע Validation, ממפה לתרחישי השימוש ומחזיר JSON או `ProblemDetail`.
- `infrastructure` מממש חיבור לעולם החיצוני: טעינת קבצים, קריאה ל־Oref, שמירה בזיכרון ותזמון polling.
- `config` מחבר את המימושים לאפליקציה באמצעות Spring Dependency Injection.

`ShelterRepository` הוא ממשק Domain מפני שהליבה צריכה דרך לגשת למקלטים, אבל אינה צריכה לדעת אם הם הגיעו מ־JSON, ממסד נתונים או משירות חיצוני. המימוש הנוכחי הוא in-memory ונמצא ב־Infrastructure.

## הרצה מקומית

דרישות: Java 21 ו־Maven.

```bash
cd fireRoute
mvn spring-boot:run
```

לאחר העלייה:

- האפליקציה: `http://localhost:8080/`
- Swagger UI: `http://localhost:8080/swagger-ui/index.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

ברירת המחדל היא מקור התרעות מדומה ובטוח לפיתוח. להפעלת המקור האמיתי:

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--fireroute.alerts.source=oref"
```

חשוב: endpoint פיקוד העורף אינו API ציבורי רשמי, עשוי להשתנות ללא הודעה ונגיש בדרך כלל רק מתוך ישראל. לכן כל כשל בו הופך ל־`UNKNOWN` ולא ל־`QUIET`.

## בדיקות ובנייה

```bash
cd fireRoute
mvn clean verify
```

הבנייה מריצה 114 בדיקות, ובהן בדיקות יחידה, MockMvc, עליית Spring, OpenAPI ועקביות של קובצי המפה והמקלטים. בדיקות Oref משתמשות ב־fixtures וב־HTTP מדומה ואינן תלויות באינטרנט. ה־CI מעלה גם JAR אמיתי ומריץ מולו בדיקת ביצועים קצרה באמצעות k6.

בדיקות העומס המדורגות ותרחיש קפיצת המשתמשים בזמן אזעקה מתועדים ב־[docs/performance.md](docs/performance.md).

## API

התיעוד המלא, כולל פרמטרים ודוגמאות תשובה, נמצא ב־[docs/api.md](docs/api.md). פורמט השגיאות מתועד ב־[docs/api-errors.md](docs/api-errors.md), ומודל מצב ההתרעה ב־[docs/alert-status.md](docs/alert-status.md).

ה־endpoints המרכזיים:

| פעולה | Endpoint |
|---|---|
| צומת קרוב ל־GPS | `GET /api/junctions/nearest` |
| מסלול רגיל | `GET /api/routes` |
| מסלול למקלט | `GET /api/routes/emergency` |
| רשימת מקלטים | `GET /api/v1/shelters` |
| מצב התרעה | `GET /api/alerts/status` |
| הדמיית התרעה | `POST /api/alerts/simulate` |

## נתונים ואופליין

`map.json` ו־`shelters.json` תחת `src/main/resources` הם מקור האמת היחיד. בזמן build הם נארזים גם כמשאבים סטטיים. ה־Service Worker שומר אצל הלקוח את ממשק האפליקציה, הגרף והמקלטים, והדפדפן מסוגל לבצע ניתוב מקומי כשאין גישה לשרת.

אופליין אינו יכול לקבל התרעה חדשה מפיקוד העורף ללא תקשורת. לכן קיים גם כפתור חירום ידני למציאת מקלט.

## מגבלות ידועות

- השירות מוגבל כרגע למרכז תל אביב ולנתונים שבקובצי הפרויקט.
- מקור Oref אינו רשמי ולכן אין להציג את הפרויקט כמערכת מצילת חיים מאושרת.
- endpoint הסימולציה ומדיניות חסימת מסלול רגיל בזמן התרעה הם משימות hardening לפני production מלא.
- חלק מה־API נמצא עדיין תחת `/api` והמקלטים תחת `/api/v1`; איחוד מלא מתוכנן ב־BE-11.

רשימת המשימות והמצב המדויק נמצאים ב־[docs/backend-tasks.md](docs/backend-tasks.md).
