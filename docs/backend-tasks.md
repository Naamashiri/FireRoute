# FireRoute Backend — משימות לסיום

זהו מקור האמת של משימות ה־Backend. מעדכנים את הסימון רק אחרי שקריטריוני הקבלה מתקיימים ו־`mvn clean verify` עובר.

## מצב נוכחי

- **משימה פעילה:** BE-17 — הגנת endpoint הסימולציה באמצעות profile.
- **מצב build:** `mvn clean verify` עובר עם 114 בדיקות; בדיקות המערכת משתמשות בנתוני production אך לעולם אינן פונות ל־Oref החי.
- **הגדרת סיום:** כל ה־endpoints עובדים, כללי החירום נאכפים בשרת, מקור Oref בטוח, קיימות בדיקות API ואינטגרציה, והריפו נקי ומתועד.

  - נוסף כפתור חירום ידני, מפני שלא ניתן לקבל עדכון Oref חדש ללא תקשורת.

- [x] **BE-04 — להפריד חוזה ומימוש של ShelterRepository**

  - **קבלה:** Application תלויה בממשק ולא יודעת שהמידע הגיע מ־JSON.

- [x] **BE-05 — להשלים את ShelterService**

  - להחזיר חריגה ייעודית כאשר מקלט לא קיים.

  - **קבלה:** endpoints מחזירים JSON תקין ונבדקים ב־MockMvc.

- [x] **BE-07 — לקשר בין Shelter ל־Junction**

  - טעינת production מאמתת מזהים ייחודיים וקואורדינטות תקינות.
  - להחזיר פרטי מקלט בתוצאת מסלול חירום.
  - **קבלה:** אין שני מקורות מידע לא מתואמים לגבי מקלטים.

## שלב 3 — חוזה API ו־Validation

- [x] **BE-08 — להוסיף Bean Validation**
  - להוסיף `spring-boot-starter-validation`.
  - להוסיף `@NotBlank`, `@PositiveOrZero` ו־`@Valid` ל־DTOs ול־controllers.
  - **קבלה:** שדה חסר או ערך שלילי מחזירים 400 עם פירוט השדה.

- [x] **BE-09 — לאמת GPS ואזור כיסוי**
  - latitude בטווח `-90..90`, longitude בטווח `-180..180`.
  - לדחות `NaN`, infinity ונקודה רחוקה מדי מאזור השירות.
  - להגדיר מרחק snap מרבי ב־configuration.
  - **קבלה:** `lat=999` ונקודה מחוץ לתל אביב אינן מחזירות צומת כאילו הן תקינות.

- [x] **BE-10 — ליצור חריגות ומיפוי HTTP מסודרים**
  - ליצור חריגות כגון `JunctionNotFoundException`, `ShelterNotFoundException`, `LocationOutsideCoverageException`.
  - למפות דרך `ProblemDetail` את 400/404/422/500 הפעילים כעת; 409 ו־503 יתווספו במשימות המדיניות שיוצרות אותם (BE-18 ו־BE-15).
  - **קבלה:** כל סוג כשל מקבל status ומשמעות עקביים.

- [ ] **BE-11 — להעביר את ה־API ל־`/api/v1`**
  - לעדכן controllers, frontend, Swagger ובדיקות.
  - **קבלה:** כל endpoints של ה־Backend זמינים תחת `/api/v1` בלבד.

## שלב 4 — להשלים את מערכת ההתראות

- [x] **BE-12 — לתקן את parser של Oref**
  - body/מערך ריק חוקי → `QUIET`.
  - מערך לא ריק → `ACTIVE`.
  - JSON שבור, `data` חסר או מסוג שגוי → `UNKNOWN`.
  - HTTP שאינו 200 או timeout → `UNKNOWN`.
  - **קבלה:** שינוי schema לעולם אינו מתפרש בטעות כ־QUIET.

- [x] **BE-13 — לסנן התרעות לפי אזור השירות**
  - להתאים את רשומות `data` לשמות האזור המוגדרים ב־configuration.
  - להוסיף fixtures ובדיקות לאזור מתאים ולאזור אחר.
  - **קבלה:** התרעה מחוץ לתל אביב אינה מפעילה את FireRoute בתל אביב.

- [x] **BE-14 — ליצור מצב התראה עשיר**
  - להחליף boolean בלבד ב־snapshot עם status וזמנים.
  - לכלול `lastAttemptAt`, `lastSuccessfulReadAt` ו־`lastChangedAt`.
  - לשמור את העדכון thread-safe.
  - **קבלה:** ניתן להבחין בין QUIET עדכני, UNKNOWN ומידע ישן.

- [x] **BE-15 — לשפר Alert Status API**
  - להחזיר status, זמני עדכון ו־`stale`.
  - להגדיר `stale-after-seconds` ב־configuration.
  - **קבלה:** הלקוח יודע אם מצב ההתראה עדכני.

- [x] **BE-16 — ליצור AlertMonitoringService**
  - להשאיר ל־`AlertPoller` רק את התזמון.
  - להעביר ל־Application את הקריאה למקור ומדיניות עדכון המצב.
  - להזריק `Clock` לבדיקת זמנים.
  - **קבלה:** אפשר לבדוק את מדיניות ACTIVE/QUIET/UNKNOWN ללא Spring Scheduler.

- [ ] **BE-17 — להגן על endpoint הסימולציה**
  - לחשוף אותו רק בפרופיל `demo`/`local`.
  - לוודא שב־production הוא אינו קיים.
  - **קבלה:** בדיקת context מאמתת 200 בדמו ו־404 בפרודקשן.

## שלב 5 — מדיניות ניתוב חירום

- [x] **BE-20 — להשלים סיבות כשל בנתיב**
